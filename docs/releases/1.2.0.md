# Material Boot 1.2.0

**Read this first: this release removes the `material-grub` command and the old graphical editor.** By semantic versioning that is a breaking change and would be a 2.0.0; it ships as 1.2.0 because the maintainer decided to do the whole clean-up in one release. Nothing of yours is lost: your settings, colours, names, icons, presets and entry order are kept, and every file that is removed is backed up first. What replaces what:

| before (1.1 and older) | now |
|---|---|
| `material-grub apply`, `doctor`, `preview`, `ventoy`, `uninstall` | `material-boot grub apply`, `doctor`, `preview`, `ventoy`, `uninstall` |
| `material-grub colour`, `conf`, `presets`, `overrides` | `material-boot core colour`, `conf`, `presets`, `overrides` |
| `material-grub gui` and the old "Material GRUB" launcher | `material-boot ui` and one **Material Boot** launcher |
| `material-grub update`, `version` | `material-boot core install` (updates), `material-boot version` |

Typing an old word prints where it went. Anything of yours that calls `material-grub` (a script, an alias) needs the new words.

## What is new

- **One way in.** `sudo ./install.sh` shows one screen (parts, the look with a preview, each part's questions) and one progress view with a live clock on long steps, so nothing looks stuck. **On a machine that is already set up it first asks whether to keep your current look and settings or edit them now**, and it only touches what changes. `-v` shows the details, `-q` only the result; everything is kept in `/var/log/material-boot/install.log`.
- **One editor for everything: `material-boot ui`.** The web editor moved into the core and edits GRUB, Plymouth and Ventoy in one place, with a live preview. It is installed by default on a machine with a graphical session (`--without ui` skips it) and shows the pages of the parts you have.
- **Leftovers are cleaned up.** The old command and the old editor (and its launcher) are listed on the screen, backed up, then removed. Files a package owns are only named.
- **Help you can rely on.** `material-boot help`, `material-boot <command> --help` (it explains and never runs the command), `material-boot help <part>` and a man page, all made from one table and tested against what the commands accept ([commands.md](../commands.md)).
- **Plymouth and GRUB report what they do** and the installer installs what Plymouth needs (found on a real Fedora machine in 1.1.1).
- Fixes: `material-boot version | head -1` no longer prints a traceback; the kernel hooks (Debian, Arch) call `material-boot grub apply`.

## Upgrading

Install the new bundle over the old one (`sudo ./install.sh`) or update the packages. Packages: `material-boot-core` now ships the editor and obsoletes `material-grub-gui`; `material-grub` and `material-plymouth` need `material-boot-core` 1.2.0 or newer.

## Tested

- Unit tests of every new piece, each checked by deliberately breaking the code (the test must fail).
- **A real update from the released 1.1.1 bundle to this one in containers** (Fedora and Debian; Arch and Ubuntu as listed in the pull request): the old command and editor are removed and backed up, settings, colours and per-entry overrides are kept, Plymouth stays applied, a kernel-change cycle works with the new hook, a second run changes nothing.
- The editor in Chrome end to end (every page, Apply through the real helper in a scratch root, Ventoy drawn with the real GRUB package) and over HTTP in the installed system.
- The installer screen driven by keystrokes on a terminal in containers.

**Not tested yet:** booting a real machine into the new menu or splash from this release; immutable systems (the editor is not offered there); other terminals than the ones in the tests; the package builds of this exact release outside CI; polkit asking for the password on a real desktop (the helper's checks are tested, the prompt itself is the system's).
