# Material Boot 1.1.0

**The installer has a screen.** Run `./install.sh` in a terminal and it now asks what to install and how you want it to look, in colour, with a drawing of the look you are choosing, before it changes anything.

## What's new
- **A checklist of what to install.** Material GRUB and Material Plymouth, with what is installed already marked, and a line for each saying what it is.
- **The look, with a preview.** Style (rail, clean, list, split), dark or light, **one seed colour or every distro in its own colour** (32 named colours with a swatch each, or any `#RRGGBB`), the cookie and the firmware logo, and the key hints. A small drawing of the layout in your chosen colours follows the highlighted option.
- **Each part asks its own questions.** GRUB: screen resolution, raw entry names, the countdown bar, the timeout, the graphical editor. Plymouth: the loading bar, how much moves, and who edits the kernel command line. A part brings its questions in its own manifest (`install.questions`, in `docs/plugins.md`), so other parts can do the same.
- **A summary before anything changes**, with the exact command that does the same without the screen. Confirming the summary is the confirmation: you are not asked "Continue?" a second time.
- **Updates stay quiet.** On a machine that already has Material GRUB the screen only asks which parts to install (and about a part that is new); `--tui` shows the whole screen anyway.
- **Nothing changes for scripts.** `--yes`, `--dry-run`, `--no-tui`, `--progress json`, a package install or `--root` never show the screen, and every answer is also an option as before.

## Good to know
- It needs a terminal. With `TERM=dumb` or a pipe you get the same questions as plain numbered prompts; in a terminal with fewer than 256 colours the screen works but leaves the drawing out. If the window is smaller than 50 x 12 it asks you to make it bigger.
- The preview is a **drawing of each style's layout** in your colours, not a picture of the real menu (the real one needs the shared data, which only exists once the install has run).
- Material GRUB and Material Plymouth are **1.1.0** too, and the bundle (`material-boot-1.1.0.tar.gz`) carries them. The parts work with an older core as before; they just do not show these questions there.
- Not in this release: starting from a saved preset, and changing single entries' names and colours while installing (the graphical editor is the place for that).

## How we tested it (and what we didn't)
The screen was driven with the keyboard on a real terminal (a pty with 256 colours) in unit tests and in a Fedora container: the list style, the countdown bar off and a 7-second timeout were chosen, GRUB installed with exactly those settings, and removal put `grub.cfg` back as it was. The screens are compared with stored copies at 80x24 and 120x40, and deliberately broken versions of the code fail the tests. I also looked at the screen through a terminal emulator.

**Not tested yet:** how it looks in other terminals than xterm-compatible ones (fonts, colour fidelity), a real computer (graphics hardware, firmware, an encrypted root disk), and immutable systems. The Plymouth questions are checked as data and by the same screen code, but Plymouth was not installed through the screen in a container.
