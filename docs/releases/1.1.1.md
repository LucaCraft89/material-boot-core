# Material Boot 1.1.1

A fix for a crash on machines that had the **graphical editor from Material GRUB 0.7.x**, and two things the new installer screen was missing.

## What was wrong
- **The installer stopped with `KeyError: 'gui'`** on a machine where an older Material GRUB had installed its graphical editor: the install record still named it, but nothing provides it any more, and the installer did not expect that. A name in the record that no part provides is now ignored, and nothing else about it changes.
- **The screen did not say what was already installed.** On an update it only asked which parts to install. It now begins with **"On this system"**: each installed part with its version and what this run will do (update, install again, or leave alone because yours is newer), and a note that your settings are kept. The same block is repeated in the summary before you confirm.
- **It did not say where to customise further.** On an update the screen asks only which parts to install, because your look and settings are kept; the style, colours and per-entry options you saw before are not asked again. The summary and the end of the install now list where to go: `material-boot core colour` (one colour for everything, or one per entry), `material-boot core overrides` (names, colours and icons of single entries, their order, hidden ones), `material-boot core presets`, `material-boot core conf`, `material-grub gui` (the graphical editor) and `./install.sh --tui` (the whole screen again, with every look question).

## Good to know
- Material GRUB and Material Plymouth stay at 1.1.0; the bundle is `material-boot-1.1.1.tar.gz`.
- `./install.sh --tui` shows the style, scheme, colour and logo questions even when Material GRUB is installed already.

## Tested
New tests reproduce the crash with a record that names a part nobody provides (both the command and the part selection; they fail on 1.1.0). The lines about what is installed are tested for each version case, on the first screen, in the summary and in the plain prompts; the list of commands is checked against the real commands.

**Not tested yet:** this on your machine (the crash was found there), a real computer boot, other terminals than xterm-compatible ones, and immutable systems.
