# Material Boot 1.0.0

**This is the release to download.** Material Boot is the GRUB theme ([Material GRUB](https://github.com/LucaCraft89/material-grub)), the matching boot splash ([Material Plymouth](https://github.com/LucaCraft89/material-plymouth)) and the shared code under both. The tarball attached to this release (`material-boot-1.0.0.tar.gz`) has all of it and one installer.

## Highlights
- **One installer.** Fresh system: Material GRUB. Already installed: updated in place, **settings kept**. Add the boot splash with `--with plymouth`. Remove what you don't want with `--uninstall` (`--only grub` or `--only plymouth` to take out one part and leave the rest).
- **A `material-boot` command.** `material-boot grub ...`, `material-boot plymouth ...` and `material-boot core ...` (colours, presets, per-entry customisation, health checks `doctor`, updates). The old `material-grub` command keeps working as before.
- **Look at it before you let it change anything.** `./install.sh --dry-run` lists what would change and touches nothing (no root needed).
- **Safe by design.** Every step is checked, backed up and undone if it fails; the installer refuses downgrades and tells you what it found before it changes it.
- **Shared by both parts**, so the GRUB menu and the boot splash always use the same colours, palettes, distro list and settings.

## Install
```
sha256sum -c material-boot-1.0.0.tar.gz.sha256
tar xzf material-boot-1.0.0.tar.gz && cd material-boot-1.0.0
./install.sh --dry-run
sudo ./install.sh                    # core + Material GRUB
sudo ./install.sh --with plymouth    # also the boot splash
```
Needs Python 3.9 or newer (the installer finds it, or tells you what to install). The bundle verifies itself against its own checksums.

## How we tested it (and what we didn't)
Installed from this very bundle in containers on Fedora, Debian, Ubuntu, Arch and openSUSE: dry run, GRUB, the boot splash with a real initramfs rebuild, health check, and removal leaving nothing behind. A real version bump (1.0.0 to 1.0.1) through the rpm, deb and Arch package managers works. The installed result boots in a virtual machine (QEMU) with the Material theme.

**Not tested yet:** a real computer, and immutable systems (Fedora Silverblue, SteamOS and similar). Keep a way to recover your boot before trying it on a machine you can't afford to break.

## For packagers and developers
The core's own packages (rpm, deb, Arch) are built and tested in CI but not attached here. Plugin API 2 lets other packages add a part: see `docs/plugins.md`. All three repositories start at 1.0.0 and are released together.
