# Material Boot 1.0.1

A fix for the first install. **If `./install.sh` from 1.0.0 stopped with "missing: Pillow", this is the release for you.**

## What was wrong
On a machine with more than one Python (for example a distribution `python3` plus a `python3.12` in `~/.local/bin`), the installer could pick the one without the Pillow image library, and fail even though Pillow was installed for the system Python. It now uses your distribution's own `python3` first, and prefers a Python that can import Pillow.

## What changed
- **`install.sh` picks the right Python.** The distribution's `python3` first, then any Python 3.9+ that has Pillow, and only then any Python 3.9+.
- **The installer installs what it needs.** If Pillow or an SVG converter (`librsvg`) is missing, the installer now installs them with your package manager (dnf, apt, pacman, zypper, apk or xbps) and says so, as the old Material GRUB installer did. A dry run never installs anything, and neither does a package install (a package declares its own dependencies).

## Good to know
- Only material-boot-core changes: **Material GRUB and Material Plymouth stay at 1.0.0** and are fetched from their `v1.0.0` tags. The bundle you download is `material-boot-1.0.1.tar.gz`.
- Install and update exactly as in 1.0.0 (`sudo ./install.sh`, add the splash with `--with plymouth`).
- **Not in this release:** the installer has no interactive part chooser or GRUB question screen yet, only command-line options. A redesigned installer screen is planned.

## Tested
New tests reproduce the wrong-Python case with fake interpreters (they fail on 1.0.0) and cover the dependency step with a fake package manager. A Fedora 45 machine ran the 1.0.0 install with the right Python and it completed.

**Not tested yet:** a *fresh* install on a machine where Pillow is genuinely missing (the dependency step is tested with a fake package manager, not a real one), a real computer boot, and immutable systems.
