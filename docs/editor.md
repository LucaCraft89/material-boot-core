# The editor (`material-boot ui`)

Everything you can change about the look, in one place, in your browser, with a live preview. It is part of the core, so it is there as soon as Material Boot is, and its pages are the **installed parts'**: Style, Entries and Ventoy exist with Material GRUB, Boot splash with Material Plymouth; Colours, Presets, Update and Logs are the whole system's.

## Start it

- **In the applications menu: *Material Boot*** (installed by default on a machine with a graphical session; `--without ui` leaves the launcher out, `--with ui` forces it).
- **From a terminal:** `material-boot ui`. It opens your default browser at a link with a secret key that is also printed in the terminal. Closing the tab stops it after two minutes (`--idle 0` never, `--port N` picks the port, `--no-browser` only prints the address).

## What it does

- **Overview:** the versions, the health checks of every part (the same as `material-boot core doctor`), shortcuts.
- **Style** *(GRUB)*: the four layouts with a live preview, the cookie, firmware logo, key hints, raw name, countdown and timeout.
- **Entries** *(GRUB)*: drag entries (or Alt+arrow keys) to reorder the menu, *Linux first* / *Windows first*, and per entry: name, colour (32 preset colours or any `#RRGGBB`), icon (the built-in ones or your own picture), hidden, and which entries the change covers.
- **Colours:** one seed colour for everything or a colour per entry, with the resulting Material 3 palette.
- **Boot splash** *(Plymouth)*: on or off, the loading bar (an endless wave, or one that fills), how much moves (full, calm, still), and three stills (while booting, the disk password, shutting down) drawn by the splash's own code from the settings on screen.
- **Ventoy** *(GRUB)*: pick a stick, set its look, and rename, recolour and re-icon single ISOs.
- **Presets:** save the look, import and export it as a file.
- **Update:** checks GitHub for a new release only when you click; a package install is updated through your package manager.
- **Logs:** what the last Apply did.

Every control has a `?` with a short explanation. The preview is drawn by the same code that writes your real menu: nothing is written until you press **Apply**. Apply writes the settings, rebuilds the menu first and then the splash; if the splash step fails it puts everything back by itself and the new menu stays.

**Editing the kernel command line.** For the splash to show, the kernel command line needs `quiet splash` (and mkinitcpio needs its `plymouth` hook). The editor does that **only if you tick "Let Apply make these changes"** on the Boot splash page, every session: it is never saved and never assumed. Each change is backed up and undone if anything fails.

## Safety

- The page is served from `127.0.0.1` on a random port. The key in the link becomes a `SameSite=Strict` cookie and must also be sent in a header on every call, the `Host` and `Origin` headers are checked, and no cross-origin request is ever allowed, so another web page cannot talk to it. Nothing listens on the network.
- The editor never runs as root. **Apply** starts `/usr/libexec/material-boot-ui-helper` through `pkexec`: the system asks for your password or fingerprint, and the helper accepts only a fixed list of requests (`apply`, `plymouth`, `update`) on stdin, validates every value again, backs up your settings first, and restores them if applying fails.
- The helper only writes `/etc/material-grub.conf`, `/etc/material-grub/` and its backup in `/var/backups/material-grub`, then runs `material-boot grub apply` (which validates `grub.cfg` and rolls back when it is wrong) and, with Plymouth, `material-boot plymouth apply` (which backs up and verifies the initramfs and puts everything back on any failure).
- Ventoy sticks are written as you, not root: a mounted stick already belongs to you.
- Nothing is sent anywhere, except the update check you click (one request to the GitHub releases API with no information about you).

## Without a desktop

Over SSH there is no browser or password agent: use the terminal commands ([commands.md](commands.md): `material-boot core conf | colour | overrides | presets | apply`), or run `material-boot ui --no-browser` and forward the port.

## Troubleshooting

- *No password prompt*: you need a polkit agent (every desktop has one). Over SSH use `sudo material-boot core apply` after editing `/etc/material-grub/overrides.json`.
- *A page is missing*: its part is not installed (`material-boot core parts`).
- *Hide or reorder had no effect*: `material-boot grub doctor` says when `grub.cfg` must be regenerated.

## How it is built

The code is `material_boot/ui/` (a small HTTP server, the privileged `helper.py`, a web page with no build step in `web/`); the GRUB-only pages (the entry preview, Ventoy) use the GRUB part's own modules, found through its manifest. The colours of the page are generated by `scripts/gen_ui_tokens.py`. Tests: `tests/test_ui_server.py` (the server over HTTP, the helper in a scratch root) and `tests/ui_e2e.py` (Chrome, every page; the CI job `editor`).
