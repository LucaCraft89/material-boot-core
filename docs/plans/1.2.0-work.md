# 1.2.0: the work, in order (a log, kept current)

The design is [ux.md](ux.md) (decisions of 2026-11-28: initial look in the installer with "keep or edit" on an update, the editor into the core, `material-grub` removed, the editor on by default on a desktop). **All of it ships as 1.2.0** (the maintainer's decision, one release). Rule of the run: work happens on the branches `release/1.2.0` of the three repositories; **nothing is tagged until the maintainer has tried a release-candidate bundle on a real machine**.

## Facts the plan stands on
- Callers of the `material-grub` *command* (not the internal `material-grub-*` scripts, which stay under `/usr/share/material-grub/bin`): the Debian kernel hook (`packaging/debian/kernel-hook`), the Arch pacman hook (`packaging/arch/material-grub.hook`), the editor's helper (`gui/mghelper.py`, `APPLY`), `install/uninstall.sh`, and the docs. The `/etc/grub.d` hooks and the systemd unit call internal scripts, so they are unaffected.
- `material-boot grub` already has `apply`, `doctor`, `preview`, `ventoy`; the core has `conf`, `colour`, `presets`, `overrides`, `apply`, `doctor`, `install`, `parts`. What `material-grub` had and `material-boot` lacks: `update` and `uninstall` (both are `material-boot core install` / `--uninstall`), `version`, `gui`.
- The editor is `gui/` in material-grub: `mgserver.py` (875 lines), `mghelper.py` (316), `mgstate.py`, `mgpreview.py`, `mgplymouth.py`, `mgpaths.py`, a launcher, a `.desktop`, a polkit policy, and `web/` (108 KB).

## Decisions taken while building (2026-11-28)
- **The editor in the core** (work package 5): a package `material_boot/ui/` (server, state, preview, helper, plymouth page, paths, `web/`) moved from `gui/` of material-grub with its imports pointed at the core's modules. What is GRUB-specific (entry scenes for the preview, Ventoy stick detection, the GRUB state directory) is reached through the GRUB part: its entry module exports `ui_modules()` (the directory of its Python modules) and the core puts it on the path when the editor needs it. `ui` is a part the core provides itself (like `core`), default on when a graphical session is detected, `--without ui` skips it.
- **Callers of `material-grub` still to move** (work package 6), beyond those listed above: the Plymouth part's `regen_grub` (`["material-grub", "apply"]` in `plugin.py`).
- **A part that stays silent for a long step is a bug**: the Plymouth tests assert a step is announced before the command that takes the time.
